## 6. Reglas de recuperación

- Verificar GitHub `main` antes de producir trabajo sustantivo cuando el conector esté disponible.
- GitHub `main` prevalece sobre el ZIP si existe una versión canónica posterior.
- No reescribir documentos históricos para limpiar inconsistencias; conservar genealogía.
- Priorizar fuentes `APROBADO/RATIFICADO` sobre candidatas, salvo cuando el archivo aprobado remita explícitamente al contenido íntegro de una candidata.
- Mantener condiciones transportables visibles.
- No abrir F6 ni fases posteriores automáticamente.
- Resolver contradicciones por elevación explícita, nunca por corrección silenciosa.

## 7. Resultado esperado de una activación correcta

Antes de ejecutar F5, la conversación nueva debe poder explicar:

- dónde está el proyecto;
- qué está cerrado y aprobado;
- qué Gate habilita F5;
- cuál es el mandato de F5;
- qué herencias no se reinterpretan;
- qué condiciones viajan;
- qué decisiones corresponden a F5 y cuáles se difieren a F6–F8;
- qué documentos constituyen la fuente de verdad.

Si no puede reconstruir estas ocho piezas con seguridad, debe permanecer en modo recuperación/verificación.
