## 4. Reglas de recuperación

- No asumir que el kit es más reciente que GitHub `main`; verificar cuando sea posible.
- No interpretar `CANDIDATO` como `RATIFICADO`.
- No abrir F5 si el Gate no tiene decisión humana explícita.
- No reescribir documentos históricos para “limpiarlos”; conservar genealogía.
- Priorizar fuentes canónicas aprobadas sobre candidatas, excepto cuando una ratificación remita al contenido íntegro de una candidata.
- Mantener condiciones transportables visibles.

## 6. Resultado esperado de una activación correcta

La conversación nueva debe poder explicar, antes de ejecutar trabajo:

- dónde está el proyecto;
- qué está aprobado;
- qué Gate está pendiente o ratificado;
- qué F5 debe resolver;
- qué decisiones no puede reinterpretar;
- qué tensiones deben viajar;
- qué documentos son la fuente de verdad.

Si no puede hacer eso, no debe producir artefactos F5 todavía.
